# fiuhq/stricli

A fork of [bloomberg/stricli](https://github.com/bloomberg/stricli) that carries a short patch set on top of upstream `main`. Upstream is merged into `main` regularly; the patches stay on top of it.

The consumer is [fiu-cli](https://github.com/fiuhq/core/tree/main/packages/fiu-cli), which copies `packages/core` byte for byte into `packages/fiu-cli/vendor/stricli/core` at a pinned commit of this fork. Bun cannot install one package out of a monorepo from git, so the copy stays; the patches live here.

## Patch set

Every changed source file under `packages/core/src` carries an Apache-2.0 §4(b) modification notice below Bloomberg's copyright header.

Behaviour is unchanged, and the file compiles the same under both settings.                                                                                                                                                                  |
| `packages/core/src/routing/scanner.ts`                         | An input that names no route falls through to the route map's `defaultCommand` only when it starts with `-` or that command accepts a positional (`acceptsPositionalInput`). A bare word under a map whose default takes no positionals was then refused as `Too many arguments, expected 0` against the default, instead of as an unregistered route with close-match suggestions. That default could only ever refuse the word, so nothing that ran before stops running. Flags, and defaults that take positionals, route exactly as upstream. |

| `packages/core/tests/routing/scanner.spec.ts`                  | The two "route map with default command" cases for a bare unknown word now expect the route-not-found error, and a new "route map with default command that takes positionals" block covers the defaults and flag-shaped tokens that still fall through | They asserted upstream's fall-through, which the routing patch above replaces; the new cases pin the conditions under which the default is still reached.                                                                                                                                                                                                                                           |

## Merging upstream

Merge `bloomberg/stricli` `main` into `main` with a merge commit, never a rebase or squash, so upstream's history stays in the fork. A conflict in a patched file keeps upstream's change and re-applies the patch on top of it.
